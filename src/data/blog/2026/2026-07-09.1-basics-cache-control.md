# Back to Basics: Caching with Cache-Control header

Today I was dealing with a simple caching issue with our Vite app - the `translations.json` file was being cached by the browser and not being updated when we deployed a new version of the app. This was causing the app to display old translations / missing the new translations.

Browser caching is a must have attribute for any web application. So here's a really quick cheat sheet of the Cache-Control header and how to use it.

## Cache-Control Header options

| Directive           | What it means                                                                            | Simple example                                                             | Exact header key/value                               |
| ------------------- | ---------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- | ---------------------------------------------------- |
| `no-cache`          | Store it, but revalidate with the server before reuse.                                   | `index.html` that should be checked for updates on each visit.             | `Cache-Control: no-cache`                            |
| `no-store`          | Never store it; fetch it every time.                                                     | Banking or one-time token responses.                                       | `Cache-Control: no-store`                            |
| `max-age=<seconds>` | Treat as fresh for this many seconds, then revalidate.                                   | `Cache-Control: max-age=3600` for an image that can stay fresh for 1 hour. | `Cache-Control: max-age=3600`                        |
| `immutable`         | While fresh, the response is treated as not changing, so the browser skips revalidation. | Fingerprinted app bundle like `app.8f3a1.js`.                              | `Cache-Control: public, max-age=31536000, immutable` |
| `public`            | Any cache may store it, including shared caches (CDN/proxy).                             | Public product images cached at browser + CDN.                             | `Cache-Control: public, max-age=86400`               |
| `private`           | Only a user-specific cache may store it; shared caches must not.                         | User account dashboard JSON cached only in the browser.                    | `Cache-Control: private, max-age=300`                |

Common combined policies:

- Versioned static assets (hashed JS/CSS/images): `Cache-Control: public, max-age=31536000, immutable`
- HTML documents: `Cache-Control: no-cache, must-revalidate`
- User-specific API responses: `Cache-Control: private, no-cache`

## TL;DR - So what should I be using?

- Static assets (JS/CSS/images) should have a UNIQUE file name (hash) which all modern front-end build tools do authomatically. e.g. `app.8f3a1.js` or `style.9c2b4.css`. These should be cached for a long time (1 month or even 1 year) and marked as immutable. This content never changes and will be cached upstream via CDN's and in the browser. When a new version is deployed, the file name changes and the browser will fetch the new file.
- HTML documents should be cached for a short time - 5 minutes or 1 hour or 1 day .. whatever feels comfortable with how long the file might change and be redeployed. Marked these as `no-cache`. This content changes frequently and should be revalidated with the server on each request. This gives you the best of both worlds - checks the server first for a nerwer version (this check is a small network request) and if the file hasn't changed, the browser will use the cached version (no network traffic). If it has changed, the browser will fetch the new version (full network traffic/file size).

** Don't be fooled by the `no-cache` directive** - it does not mean "don't save/cache this file". That's what `no-store` means.

## Sample code

### .NET Core (ASP.NET Core)

Set long-lived caching for static files, and revalidation for HTML:

```csharp
using Microsoft.AspNetCore.Http.Headers;

var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

app.UseStaticFiles(new StaticFileOptions
{
    OnPrepareResponse = context =>
    {
        var headers = context.Context.Response.GetTypedHeaders();

        // Fingerprinted assets: public, long cache, immutable
        headers.CacheControl = new CacheControlHeaderValue
        {
            Public = true,
            MaxAge = TimeSpan.FromDays(365),
            Extensions = { new NameValueHeaderValue("immutable") }
        };
    }
});

app.MapGet("/", async context =>
{
    context.Response.Headers.CacheControl = "no-cache, must-revalidate";
    await context.Response.SendFileAsync("wwwroot/index.html");
});

app.MapGet("/api/me", (HttpContext context) =>
{
  context.Response.Headers.CacheControl = "private, no-cache";
  return Results.Json(new { name = "Pure Krome" });
});

app.Run();
```

### Cloudflare (Worker)

Set different Cache-Control headers based on request path:

```javascript
export default {
  async fetch(request, env, ctx) {
    const url = new URL(request.url);
    const response = await fetch(request);
    const headers = new Headers(response.headers);

    if (url.pathname.match(/\.(js|css|png|jpg|jpeg|webp|svg|woff2)$/)) {
      headers.set("Cache-Control", "public, max-age=31536000, immutable");
    } else if (url.pathname === "/" || url.pathname.endsWith(".html")) {
      headers.set("Cache-Control", "no-cache, must-revalidate");
    } else if (url.pathname.startsWith("/api/me")) {
      headers.set("Cache-Control", "private, no-cache");
    }

    return new Response(response.body, {
      status: response.status,
      statusText: response.statusText,
      headers,
    });
  },
};
```
