# Docker Engine: Install free version with no Licensing issues

Docker _DESKTOP_ is the most popular way to run Docker on Windows, Linux and Mac. However, [Docker Desktop is not free](https://www.docker.com/pricing/) for all users. If you are a business with more than 250 employees or more than $10 million in annual revenue, you will need to pay for a Docker subscription to use Docker Desktop.

But what people don't realise is that the Docker _ENGINE_ is still free to use, and you can install it without any licensing issues. The Docker _DESKTOP_ application is just a GUI wrapper around the Docker _ENGINE_, which is the core component that runs containers.

NOTE: Yes, the GUI is nice and very convenient - but not a hard requirement at all! You can do everything via the Terminal, directly against the Docker Engine!

# Installing Docker Engine

I primarly work on Windows. So I'll break this up into two sections - Linux (first) and then Windows (second). If you are on Mac, the Linux instructions will work for you too.

## Linux / WSL

1. Jump into WSL Ubuntu:

```powershell
wsl
```

2. Update your package index and install required packages:

```bash
sudo apt update && sudo apt upgrade -y
```

3. Install Docker Engine:

```bash
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
```

4. Add your user to the Docker group to run Docker commands without `sudo`:

```bash
sudo usermod -aG docker $USER
```

5. Log out and log back in to apply the group changes, or run:

```bash
exit
```

```powershell
wsl --shutdown
wsl
```

6. Verify Docker Engine is installed and running:

```bash
docker --version
```

## Windows 11

So right now, we have Docker Engine running 100% under WSL. Win! 🎉  
Next we need to make it "easy" for Windows users to run Docker commands without having to jump into WSL every time.

To do this, there's a few more complex steps (compared to above) about setting up ports and environment variables. Lets do it!

1. Expose the daemon TCP port in WSL so Windows can reach it. Staying in WSL:

```bash
sudo nano /etc/docker/daemon.json
```

Then add the following content to the file:

```json
{
  "hosts": ["tcp://0.0.0.1:2375", "unix:///var/run/docker.sock"]
}
```

Save the file:

```
Ctrl+O, Enter, Ctrl+X
```

2. Verify the changes are correct:

```bash
python3 -m json.tool /etc/docker/daemon.json
```

3. Restart the Docker service:

```bash
sudo pkill dockerd
sudo dockerd > ~/dockerd.log 2>&1 &
```

4. Verify the Docker Engine is listening on the TCP port:

```bash
curl http://localhost:2375/version
```

5. Now, on Windows, we need to set the `DOCKER_HOST` environment variable so that Docker CLI knows where to find the Docker Engine. Open PowerShell and run:

```powershell
[Environment]::SetEnvironmentVariable("DOCKER_HOST", "tcp://localhost:2375", "User")
```

6. Verify that Docker CLI can communicate with Docker Engine.

- CLOSE and reopen PowerShell to apply the environment variable changes.
- Run the following command:

```powershell
$echo $env:DOCKER_HOST
```

You should see:

```
tcp://localhost:2375
```

7. Finally, test Docker CLI commands:

```powershell
curl http://localhost:2375/version
```

So far so good! We can connect to Docker Engine from Windows without any licensing issues. But we still cannot use the `docker` command (which is a wrapper to the Docker Engine API) directly from Windows. To fix this, we need to install the Docker CLI on Windows.

8. Install the Docker CLI on Windows

```powershell
winget install Docker.DockerCli
```

Close and Reopen PowerShell to apply the changes. Now you can run Docker commands directly from Windows.

```powershell
docker --version
docker ps
```

Happy coding!
